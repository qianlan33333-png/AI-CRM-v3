## 3. 标准组件专项

| 组件 | 统一能力与边界 |
|---|---|
| 标签选择器 | 分组、搜索、单选/多选、已选回显、移除和数量提示；区分标签来源与可选范围。确认选择不自动给客户打标。 |
| 群聊选择器 | 搜索、分页、多选、已选回显与不可选原因；真实群聊使用领域提供的 `chat_reference`，与群邀请素材分开，不能混用标识。 |
| 客服/员工选择器 | 搜索、单选/多选、已选回显和目录刷新；按调用页面授权范围读取。刷新失败保留原列表与选择，不默认套用群运营范围。 |
| 话术＋素材编辑器 | 文本编辑、允许的变量插入、素材添加与排序、删除、预览、校验和只读展示；固定话术与 Prompt 保持清楚区分，按业务场景提供能力。 |
| 素材选择器 | 统一图片、附件、小程序等类型的浏览、筛选、预览、单选/多选与回显；展示失效及不可用原因。上传入口由调用场景和权限决定。 |
| 内容预览与只读详情 | 编辑预览和保存后详情复用同一套内容呈现规则，保持文字、变量、素材顺序一致；明确预览、保存和实际发送结果的区别。 |
| 通用基础组件 | 统一筛选栏、日期范围、表格、分页、批量操作、状态标签、详情抽屉、确认框、Toast，以及加载、空态、失败和无权限状态。 |

所有选择器共同遵循：调用方明确数据来源、授权范围、选中值、单/多选、数量限制及只读状态；服务端继续执行权限校验。弹窗内先维护临时选择，确认后才回传；取消不改原值，重复打开正确回显。搜索结果乱序返回时不覆盖新结果；分页不丢选择，失败不清空已有内容。已失效或失去权限的选中项明确提示，不静默删除或替换。支持键盘操作、焦点回收和窄屏适配；不同实体标识不能互相替代。

话术与素材组件只负责编辑、校验和展示。保存、上传、发送、调度及 Provider 调用继续由所属业务模块承担；预览不能触发真实发送。

组件统一放在 v3 拥有的共享层，扩展现有 Host/Adapter，保持冻结 donor 不变。建立组件目录、调用页面清单和状态示例页，业务页面不得再维护平行实现。公共用户页面不挂载后台客服、群聊等内部选择能力。

## 4. 经营首页与全页面改造

首页保留 `/admin`，按统计范围→核心指标→经营趋势→分销概览→待办异常与入口组织。核心指标为确认支付金额、支付订单数、支付客户数、新增客户数；补充退款金额和净收款。分销区分期间业绩、待结算和已结算金额。

新增只读 `GET /api/admin/overview`，返回统计区间、指标、趋势、更新时间及分区数据状态。overview 经各领域稳定 Read Port 获取授权范围内的汇总，webshell 只展示，不跨领域查表、不触发 Provider、不新增持久化汇总表。

统计采用北京时间，金额按最小货币单位计算并保留币种；支付和退款分别按确认时间计算。客户使用 canonical customer 去重，迁入时间不冒充新增时间。无权限、不可用、未知和真实零值分别呈现，指标下钻保持相同统计口径。

后台导航调整为总览、客户、运营、交易、分销、内容素材、系统设置，保留旧链接兼容与既有权限，安全配置继续仅向超管开放。

重点模块：分销管理统一指标/筛选/表格/详情抽屉/异常处理反馈，突出佣金状态与订单证据；运营闭环统一客服群聊选择、话术素材编辑和只读详情，清楚呈现计划批次准备执行回执，保留标题封面发送约束；用户档案统一身份摘要、标签选择、业务记录及详情展示，保持 OneID 客户归属规则；素材库库内浏览与业务页选择共用规则；自动化话术复用话术素材编辑、变量插入、预览，保留 Prompt 配置。

商品编辑页保留启用分销开关，分销配置只在售卖信息显示，开关下方仅配置本商品比例与等待天数；页面素材、购买后动作、企微标签、外部推送均不显示。商品编辑页移除分销员申请入口、链接、复制按钮和二维码，公共分销中心不变。保存其他维度不能覆盖分销值，切换 tab 保留草稿。

### 交易订单中的分销事实

交易列表在授权范围内展示归因分销员与佣金状态摘要；订单详情展示该订单成交时冻结的佣金比例、归因分销员、佣金金额和币种、退款复核等待期、预计结算时间，以及实际结算／分账时间、状态与异常证据。预计时间与实际时间必须分列呈现，不能以预计时间冒充已分钱，也不能用商品当前比例替代订单成交时快照。

未参与分销、数据未知、无权限和真实零佣金分别展示。列表摘要不得据此推断订单归因；详情中的任一字段缺失均按该字段的可用状态呈现，不补造比例、人员、时间或状态。

订单页面只经 distribution 的稳定 Read Port 读取订单级分销事实，并保留交易领域的既有订单读取边界；不得跨领域查表、写入佣金记录或触发分账。若现有 Read Port 尚未提供订单快照、复核期、预计／实际结算时间、状态或证据，先由分销领域扩展版本化只读合同并完成真实数据验收，再挂载 UI。

### 用户补充

全局文本搜索使用 Enter 或明确的搜索按钮提交。渠道码中心必须修复逐键搜索打断中文输入：`input`／composition 期间不搜索、不重绘，确认中文候选的 Enter 不能触发搜索，也不能拦截浏览器对候选词的默认确认。普通 Enter 才提交当前 draft；空词 Enter 回到该页面当前已加载的全量结果；清空／重置同步清除已提交条件。翻页与刷新始终使用已提交条件，旧查询响应不能覆盖新查询结果，取消选择器不改原值。

搜索第一批只覆盖组件清单中登记的精确搜索控件。其实现和实际宿主范围以执行状态为准；其他页面必须按真实 Host、查询边界和错误语义逐页接入，不能因共享模块存在而视为全局完成。每个接入项都覆盖真实 composition、候选确认、普通 Enter、清空、刷新、分页与异步乱序。

其余后台页面全部纳入同一清单。企微侧边栏采用窄屏组件适配并保留上下文授权；商品、支付、问卷及分销主页分别优化主要操作与成功、失败、恢复状态。

## 5. 实施顺序与验收

1. 页面组件盘点、业务判断、GitHub 参考、综合 PRD 以及主线缺失前端一致性 Skill 补齐。
2. 创建图像模板统一视觉变量，完成标准组件与状态示例页。
3. 完成后台导航、经营首页和只读汇总。
4. 逐项完成 5 个重点模块并验证组件真实接入。
5. 完成其余后台、企微 sidebar 及全部用户展示页。

root 负责分发审核，Terra high/xhigh 开发，Luna max 基础执行审计。每个 PR 交付一个可观察能力。

验收：所有实际调用页覆盖搜索、回显、确认、取消、刷新、失败、权限变化和多选；编辑、预览、保存、详情一致，重复点击不重复业务操作；订单分销信息须以权威订单快照与真实分钱事实回读，分别覆盖未分销、未知、无权限、退款复核、预计结算、已结算和异常证据；所有页面状态逐项通过，后台 1280/1440、sidebar 360/420、用户 375/390/430 视口均验证；首页与明细一致，退款、迁入、跨午夜、权限差异和单领域故障均有验证；支付、问卷提交、分销归因、运营执行合同不退化；运行受影响的 typecheck、build、shell、Journey，并与同视口参考对照；发布后分别进行版本、页面回读和业务验收。

最终交付：图像模板、全局 PRD、标准组件目录与示例、全部改造页面、组件及逐页验收记录。
