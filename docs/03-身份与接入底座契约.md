## 1. 能力所有权

| 能力 | Owner | 拥有的数据 | 不负责 |
|---|---|---|---|
| platform | crm-platform | audit、idempotency、webhook inbox、session 基础设施 | 客户和身份规则 |
| identity | crm-core | customers、customer identities、证据、冲突、归并血缘 | 员工授权、Provider 网络调用 |
| access | crm-core | admin users、roles、sessions、login audit | 外部联系人身份 |
| wecom | crm-connectors | 企微 OAuth 状态、回调协议、员工与客户跟进关系 | 客户画像和 CRM 业务数据 |
| webshell | crm-ui | 模板、静态资源、导航和空状态 | 业务状态和跨域写入 |

跨域只允许使用 `port`、稳定值对象或 Composition Root 注入的 Handler 依赖。HTTP 层不得把请求字段升级为 verified identity。

## 3. 身份与错误语义

- `Resolve` 只返回 `found`、`not_found` 或 `conflict`，不得隐式建客。
- 建客只接受内部 Provider Adapter 产生的 `VerifiedFact`。
- 相同活动身份键只能属于一个 Customer；并发插入以数据库唯一约束裁决。
- 跨 Customer 根的强证据先生成 merge candidate；不得按 ID、时间或字段数量猜主根。
- 两个不同的活动强企微身份连接时记录 conflict 并失败关闭。
- 归并保留来源 Customer、身份变更前快照、操作者和证据；撤销必须验证没有后续归并。
- 支付宝首期只存在 kind、scope 校验和 Provider port，不存在 HTTP route、凭证或网络 Adapter。

统一错误码至少包括：

- `invalid_request`
- `authentication_required`
- `permission_denied`
- `csrf_required`
- `invalid_oauth_state`
- `identity_not_found`
- `identity_conflict`
- `merge_not_reversible`
- `wecom_signature_invalid`
- `wecom_callback_expired`
- `wecom_corp_mismatch`
- `provider_unavailable`

## 4. 前端壳行为

- 管理后台保留供体仓完整菜单结构；只有登录、首页、员工权限和 OneID 基础查询连接真实接口。
- 未实现模块进入统一占位页，不请求旧接口，不显示 fixture 或伪造统计。
- 侧边栏活动 Host Adapter 保留供体壳的视觉结构，只展示核心画像、问卷、商品、订单、优惠券、素材六个一级页签，并连接 v3 稳定 Port。
- 侧边栏上下文只使用配置企业、已认证员工 Session、当前 JSSDK `external_userid` 三元组；OneID 只解析既有 canonical Customer，不隐式建客，也不查询或校验本地跟进关系。
- 本模块不读取聊天、其他客服消息、CRM 标签、跟进成员、运营或自动化摘要；企微标签由企微客户端原生显示。
- 管理员 Session、侧边栏员工 Session、Customer Context Token 是三个独立凭据，禁止互换。
