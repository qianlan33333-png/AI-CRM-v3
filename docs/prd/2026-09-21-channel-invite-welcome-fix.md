# 渠道欢迎语与群邀请链接边界修复

## 业务判断

- `/gi/<token>` 是群邀请计划入口，只负责展示当前群二维码并引导入群。
- 渠道欢迎语只在联系人通过渠道码的二维码或企微获客链接完成渠道回调后执行。
- 不把群邀请访问伪装成渠道回调，避免错误归因、重复欢迎语和错误客服分配。

## 当前缺陷

1. 群邀请公开页把 `wework.qpic.cn` 二维码作为外部图片加载，但全局 CSP 仅允许 `img-src 'self' data:`，浏览器拦截图片。
2. 管理端同时展示群邀请素材和渠道欢迎语，缺少链接边界提示，容易把 `/gi/` 链接当成渠道码链接使用。

## 修复范围

- 仅对 `/gi/` 公开页面将受控的 `https://wework.qpic.cn` 加入 `img-src`，不放宽管理端或 API 页面。
- 在群邀请公开页说明该入口只用于入群，不触发渠道欢迎语或入渠标签。
- 在渠道欢迎语配置页说明欢迎语需要使用本渠道二维码/获客链接触发；群邀请链接只负责入群。
- 不修改渠道回调、OneID、External Effects、欢迎语发送状态机或生产数据。

## 验收标准

- `/gi/<token>` 页面中的有效企微二维码 `naturalWidth > 0`，截图不显示破图。
- `/gi/<token>` CSP 包含 `https://wework.qpic.cn`，普通管理端和 API CSP 不包含该外部图片源。
- 管理端文案明确区分渠道码链接与群邀请链接。
- 现有群邀请和渠道欢迎语测试保持通过。

## 架构分类

```text
OneID：不涉及；本修复不解析或绑定客户身份。
Persistence：stateless；仅修改响应头和静态说明文案。
External Effects：不涉及；不新增或重放任何 Provider 写入。
```

## 参考与复用

- 复用现有 `securityHeaders` 中按路由收紧 CSP 的机制。
- 复用现有邀请公开页模板与渠道表单模板。
- CSP 参考 MDN Content-Security-Policy `img-src` 的 host-source allowlist 规则；公开邀请页采用最窄的固定企微图片域名。

## 发布与回滚

- 先运行受影响 Go 单测和 `dev_preflight.py fast/compile`。
- 生产部署后重新读取公开页 CSP、二维码自然尺寸和渠道/群邀请说明。
- 如公开页仍无法加载，回滚本次代码版本；不修改渠道配置或发送链路。
