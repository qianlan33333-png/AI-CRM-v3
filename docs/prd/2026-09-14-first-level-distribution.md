# CRM 一级分销：完整产品需求与实施边界

状态：已冻结，作为本轮实现和验收依据。
基线：`8f19a3155ff162407e83fc2fb7994be24e27715a`（`origin/main`，2026-09-14）。
范围：v3 单企业、一级分销。旧仓只作只读行为供体，不成为运行依赖或数据源。

## 1. 业务目标与不可变边界

完整闭环为：有效购买同一商品，获得推广资格；受控专属入口成交；支付确认后记佣；等待退款复核；微信分账；对账、解冻和售后异常处理。普通商品和周期商品使用同一规则；周期服务到期不消灭有效历史购买，自动续费不推导新佣金。

分销员端只有“推广商品”和“我的收益”两个主标签。公开分销员编号仅用于展示，任何客户归属、付款人、受益人和收款身份都以 `customers.id` 与受信 Identity/Payment 事实为准。

本能力不做二级分销，不以赠送、免费领取或人工开通权益生成资格，不把优惠前标价、运费、客户端佣金参数或浏览器身份声明当作资金事实。分销佣金是对销售订单的归因和应付义务，不变更客户归属。

## 2. 开发前分类与架构结论

```text
OneID：involved；读取 canonical customer，并通过 Identity Port 判断可信付款人/受益人身份。
Persistence：local transaction + internal durable job + Provider read + Provider write/external effect。
```

Distribution 拥有自身业务记录、审计和 outbox；不访问 Product、Order、Payment、Identity 的表。可信身份只经 `identity/port`；交易商品、付款人与受益人事实只经 `order/port`；支付确认、退款暴露、收款方和微信分账只经 `payment/port`。到期检查只复用 `internal/platform/jobqueue`，不建立 ticker、Worker、租约、重试或对账内核。

需要原子性的场合（商品与政策保存、下单与归因冻结、结算金额预留与不可变分账指令接受）均为一个 PostgreSQL Unit of Work。网络调用在事务外；未知结果沿原逻辑单号与幂等键查询或对账，绝不更换单号再次付款。

## 5. 商品政策

普通商品、周期商品编辑页提供同样的“分销设置”：默认关闭；比例 `0.00%` 到 `30.00%`（内部整数基点，`0..3000`）；等待 `0..29` 天（默认 `7`）；固定说明“仅本人有效购买过本商品，才可参与推广。”

保存商品与政策使用一个 UoW 和双方 CAS 版本。任一失败整体回滚，不能出现商品已保存而政策丢失。修改政策生成不可变新版本。新订单冻结政策版本、比例、等待天数，历史订单绝不因之后改价。复制商品必生成新商品 ID 且政策默认关闭；旧商品资格不转移。

## 6. 有效购买资格

Distribution 的专用购买证据接口只返回可解释的通过、拒绝、暂缓、读取失败或身份冲突；它绝不调用既有 `Owned` 或直接访问其他领域表。通过须存在至少一笔订单，其商品 ID 和类型精确匹配，付款人与受益人都可信对应该分销员，支付已确认成功，商品实付大于零，且该笔订单没有成功退款、处理中退款或未知结果退款。

部署时，普通微信支付与分销分账是两项独立能力。`AICRM_WECHAT_PAY_PROFIT_SHARING_ENABLED` 默认 `false`；开启它还必须同时启用微信支付和 External Effects，并提供经部署验证的 `AICRM_WECHAT_PAY_PROFIT_SHARING_PUBLIC_KEY_ID`。Composition 使用现有平台验签公钥和该 key ID 创建官方分账 SDK，不启动证书下载器。能力关闭时，商品策略和分销中心可读，但结账不创建返佣归因、不标记分账也不冻结资金；收款准备保持未就绪，不能伪造可推广或可结算状态。

| 场景 | 结果 |
| --- | --- |
| 本人原价购买；本人优惠购买且实付大于零 | 有资格 |
| 免费、赠送、仅人工权益 | 无资格 |
| 本人付款其他人受益；其他人付款本人受益 | 无资格 |
| 成功部分退款；处理中/未知退款 | 该订单不能作证据 |
| 另有一笔同商品的完整有效购买 | 可使用另一笔证据 |
| 周期商品到期 | 不影响历史有效购买 |
| 买过 A 期后购买 B 期新商品 | 不互认 |
| 历史导入订单 | 只有完整证明以上条件才可使用 |

服务端在商品清单、生成推广入口、买家创建分销订单、实际提交分账前重新检查。商品清单可使用展示缓存，后三个节点只用权威事实；读取失败、证据缺失、身份冲突一律不允许，并保留待处理原因。

资格购买订单的退款影响同一分销员、同一商品，绝不波及其他商品：处理中且无替代证据时暂停新推广和未结算佣金；失败/撤销后重新判断并恢复仍符合条件的暂停记录；成功且无替代证据时取消未提交分账佣金。已提交先核对最终结果，未支付才可取消，成功则转人工异常；已到账保留到账事实并登记资格撤销资金异常。重新购买只恢复之后的资格，不复活已取消佣金。

## 7. 注册、推广与订单归因

受可信微信登录且同意当前协议的用户，按 canonical Customer 幂等注册；同一 Customer 只能有一名分销员。重复提交返回原记录且不能生成新编号。注册成功和收款就绪分别展示。Payment 完成适用 AppID 的收款身份验证与接收方准备之前，允许浏览合格商品，但不能生成有效入口；外部分销员会话只能读取自己的资料。

可推广商品满足：分销员启用、商品可售、政策开启、本人资格有效。列表返回封面、名称、价格、比例、预计佣金、等待天数；未完成收款准备时按钮引导完善。点击推广再次检查，产生服务器控制且仅存摘要的不透明凭证。凭证绑定推广人和商品，不锁死佣金比例；下单使用那一刻的政策。浏览器不可指定佣金、金额、收款人或推广人。

订单入口保留推广上下文，穿过微信授权与登录。A 的有效链接及其转发归 A；B 的链接归 B；创建后的订单不被后续链接覆盖；普通入口无归因；凭证失效或资格不满足可普通购买但不承诺佣金；已有待支付订单沿用原归因。Order 创建订单的同一 UoW 写入订单、商品快照及 Distribution 归因冻结；不能先发布异步 created 事件再补归因。

任何推广人和付款人或受益人的可信 canonical Customer 相同，即为自购，不创建可计佣归因。

## 8. 支付后计佣与状态机

权威支付确认后，由持久化的既有支付成功事实幂等消费。一个订单、商品项、推广人组合只能生成一条初始佣金事实。未支付订单只保留归因，不进入收益金额。

```text
initial_commission_minor = floor(item_paid_minor * frozen_rate_basis_points / 10000)
due_at = payment_confirmed_at + frozen_wait_days * 24h
current_payable_minor = floor((item_paid_minor - cumulative_successful_refund_minor) * frozen_rate_basis_points / 10000)
```

商品金额为实付商品项金额，不含运费。`0%` 或不足一分时保留推广成交，佣金为零，不创建分账指令。周期商品仅对当前实际订单计佣，自动续费不计。支付确认时也复核资格退款；只有受控的新微信支付交易且正佣金才可设置需分账，历史已支付订单不得补开。

状态为：待结算、暂缓、结算中、已到账、已取消、异常。异常区分“仍欠应付”和“已到账售后”，已到账记录添加异常标记而不删除原事实。每次成功退款追加调整；申请/未知退款只暂缓；退款失败恢复原应付及到期检查；全额退款取消未支付金额；到账后退款将差额登记异常，绝不伪造追回或覆盖已付款。

## 9. 到期、分账、退款并发与对账

支付成功记佣时持久安排 Jobqueue 到期检查；进程重启可恢复。到期提交前依次确认：到达时间、支付仍成功、买家退款已明确且无在途、推广资格仍有效、应付大于零、接收方可用、原交易可分账且未截止、可分资金及商户比例满足要求。`0` 天只表示尽早检查，仍须满足微信条件。

退款和分账通过 Payment 的统一资金协调：退款优先取得控制后，分账发现退款暴露必须停；分账先接受后，退款核对在途状态和冻结资金。结算状态、金额预留、不可变指令、效果接受在一个 UoW；SDK 调用在外。相同逻辑分账永远使用相同幂等键、同一微信单号。超时或未知只准原单查询、回调或对账。

Payment 使用官方 SDK 发送并主动查询。HTTP 成功或处理完成都不是到账；必须确认指定接收方成功。确认佣金后解冻剩余商户资金；取消后只在退款需求明确时解冻不再需要的金额。截止前 24 小时的未完成记录是临期异常；超过通道期限停止自动提交，但保留未履行义务，绝不自动标为已付/已取消。

人工处理可查询最新结果，登记追回款及凭证、登记商户承担金额及原因，并记录处理人、时间、审计；不能伪造微信到账结果。

## 10. 权限、接口与页面口径

分销员只能读取本人状态、收款准备、商品、入口、汇总和明细。管理员可查询分销员、订单、异常并做有审计的人工处理；资金操作须单独授权。所有金额、接收方和状态由服务端决定。

“推广商品”显示资格已通过的商品与受控推广动作。“我的收益”显示累计推广成交额（已支付归因订单原始商品实付，退款另列）、累计产生佣金（初始累计，取消/调整另列）、未结算佣金（未到账未取消的当前应付，含暂缓和异常待付）、已到账佣金（确认实际支付累计，追回另列）。明细过滤：待结算、结算中、已到账、已取消、异常；暂缓必须展示原因；零佣金成交可看但不作待付款。

## 11. 验收矩阵与交付门槛

必须覆盖资格允许/拒绝、替代购买、周期到期、自购、转发、凭证篡改、已有待支付、政策修改、0/30/小数/低于一分、多次部分退款、资格退款暂停/取消/到账异常/重新购买、重复回调/事件重放、退款并发、分账超时、重启、临期/超期、账户异常、剩余资金解冻、本人/管理员权限、敏感信息和完整审计。

交付分别证明源代码、CI、main 合并、Linux 完整包、本机 SSH 部署、登录页面和业务 API、真实商户小额冻结及分账接收方到账。商户权限或测试条件缺失时记录具体阻塞；页面上线、HTTP 200、支付请求 accepted 或队列成功均不构成资金闭环。
