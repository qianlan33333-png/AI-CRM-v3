# 企微标签与 AI 计划详情的页头操作统一

## 业务判断

企微标签页把“同步企微标签 / 新增标签组 / 新增标签”放在内容卡片右上；AI 计划详情把“确认并发送 / 拒绝计划 / 返回一级页”放在正文工具行。这两个页面已由 V3 管理端壳提供唯一标题栏，重复操作区使页面顶部信息结构不一致。

OneID：不涉及。标签同步和 AI 计划的既有客户／员工归属、OneID 读取和范围校验不改变。

持久化和外部效果：本能力不新增读写、任务或 Provider 调用。标签同步、标签组／标签创建，以及 AI 计划确认／拒绝仍由原按钮已有监听器、CSRF／版本／幂等 token、确认提示和领域 Owner 执行。只将同一 DOM 控件移动到现有 `.admin-topbar`；不会用新按钮重新实现或直连这些命令。

## 参考与复用

- GitHub #309：V3 `pageHeaderActions` 复用唯一 `admin-topbar` 和右侧 `.admin-topbar-meta`，不创建第二标题栏。
- 现有标签适配：`RenderTags` + `tag_sync_bridge.js` 维护同步状态、错误恢复和既有标签页行为。
- 现有 AI 适配：`aiAssistantAdapter.ts` 把旧云计划路由映射为当前 V3 API；冻结计划详情脚本维护确认、拒绝、版本和发送状态。

前端组件索引命中现有 `web/v3/shared/ui/pageHeaderActions.ts`。Product Design catalog 在本会话不可发现，因此不声明已使用该路由；继续使用已批准的灰白蓝管理端视觉规范。

## 方案

扩展共享页头操作 helper，使其能够把已存在的页面控件挂入指定 owner 的页头动作容器，同时保留原 DOM 节点、监听器、disabled/busy 属性、焦点和链接 href。它不会复制、重新绑定或触发页面命令。

- 企微标签页：将同步、创建标签组、创建标签三个既有控件放入标题栏右侧；卡片保留标题和说明，不再显示平行操作区。
- AI 计划详情：将返回一级页、拒绝计划、确认并发送三个既有控件放入标题栏右侧；正文保留计划状态，移除空操作行。
- 标题栏仍只显示 V3 壳的一个 `h1`。动作的 primary/danger/disabled/busy 外观继续由原节点和全局页头动作呈现规则决定。

## 边界与验收

不改冻结 donor 文件，不改变标签或 AI 的 HTTP、身份、权限、版本、幂等、确认、任务、写入或 Provider 边界。

验收覆盖：

1. 1280 与 1440 下仅一个页头标题，所有上述操作完全位于 `.admin-topbar`；正文没有重复同名操作。
2. 标签同步仍显示已有 queued／busy／failure 状态，新增标签／标签组仍打开既有表单。
3. AI 返回仍是原链接；确认和拒绝仍先走现有确认交互，disabled/busy/版本错误及已发送状态保持原行为；浏览器测试不执行真实 Provider 发送。
4. 共享 helper 的移动、重复挂载、清理和焦点行为有单测，标签和 AI 实际页面的 Chromium 1280／1440 以及受影响 build/stage 合同通过。
