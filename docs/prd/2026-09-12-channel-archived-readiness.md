# 归档/停用渠道的扫码就绪提示

## 业务判断

渠道定义、二维码资产和扫码后的欢迎/入渠标签是三个不同事实。渠道为
`inactive` 或 `archived` 时，现有契约仍保存配置和资产历史，也可以在
Catalog 的 CAS 编辑中明确恢复为 `active`；但回调只保留可信身份、关系和
渠道归因，必须停止欢迎、分配、标签和 External Effect 的创建。

因此，仍在渠道列表或编辑页展示“下载二维码”或“生成二维码”，会让运营把
历史资产误认为当前可用于获客的载体。该页面需要把“资产可读”与“渠道业务
可验收”分开表达，并给出恢复到活动状态的正常路径。

分类：OneID 不涉及；本变更不新增持久化、内部任务、Provider 读取或
Provider 写入，也不改变现有 Channel Catalog 的 CAS、审计和 Outbox 边界。

## 范围

1. Channel Catalog 的列表和详情投影仅在 `active` 时返回
   `qr_download_url`。二维码资产状态和来源继续作为历史投影保留。
2. 冻结渠道列表适配器对 `inactive`/`archived` 行移除二维码下载入口，
   显示中文原因和“编辑后选择启用并保存”的恢复引导；查看和编辑仍可用。
3. 编辑页对 `inactive`/`archived` 渠道显示同一业务原因，移除下载和生成
   二维码操作。它保留配置供核对，再由管理员显式选择“启用”并走原有 CAS
   保存。
4. `active` 渠道的可用二维码下载路径不改变。

## 不在范围内

- 不改变归档/停用回调的 no-action 语义，不补发、重放或重试旧欢迎授权。
- 不生成二维码、不调用企微、不修改客服、欢迎内容或入渠标签。
- 不把二维码资产历史投影当作 Provider 当前可读或可用证明。
- 不增加 OpenAPI 字段、第二套身份模型、跨领域表访问或新的队列/Worker。

## 验收条件

| 场景 | 可观察结果 |
| --- | --- |
| 活动渠道且服务端有受控下载地址 | 列表和详情保留原下载入口。 |
| 停用或归档渠道，即使保留已验证历史资产 | `qr_download_url` 为空；列表没有下载入口，并说明扫码不会发送欢迎语或入渠标签。 |
| 停用或归档渠道编辑页 | 显示配置仍保留、需选择启用并保存的提示；不显示下载或生成二维码操作。 |
| 明确恢复为活动状态 | 继续走 Catalog 的版本/ETag、幂等收据、审计与 Outbox；不改编码和既有配置。 |
| 后续外部验收 | 只接受一个新的、有效期内的添加好友回调产生的欢迎意图和 Outbound 尝试证据；普通消息、旧授权或单纯排队不算欢迎成功。 |

欢迎授权的业务窗口由回调到达时间起算 20 秒。实际外部验收还必须确认该
测试关系能够产生新的添加好友回调；已存在的好友关系再次扫码不保证会返回
新的欢迎授权，且不得为测试删除或解除现有关系。

## 证据分类

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| Catalog 资产状态/历史下载投影 | 系统保留某个资产的历史记录 | Provider 此刻仍可读、二维码仍在 Provider 侧有效，或扫码后一定执行欢迎。 |
| Channel 状态为 `active` 和完整的本地配置 | 回调可进入活动渠道的欢迎/标签接受路径 | 外部 Provider 已收到欢迎，或欢迎已送达。 |
| 新回调的欢迎意图、effect receipt 与首次尝试时间 | 接受和 Outbound 尝试在窗口内发生 | 用户终端已展示消息，除非 Provider 回执能证明。 |
