## 3. 派发及完成流程

1. 先读本合同、板块 PRD、仓库 AGENTS.md 和 `skills/aicrm-v3-development/SKILL.md`，记录 OneID 与持久化分类。
2. 将需求逐项映射到旧版行为、V3 代码和测试；已有行为通过验证即可，不为凑 PR 重写。行为差异、遗留缺陷和新需求分开。
3. 首批启动 01、02、08。其余按空闲名额与接口依赖推进；可先做独立领域实现，跨板块接线等待已冻结契约。
4. 每个 PR 交付一个可观察能力或明确缺陷；复杂板块可多个 PR。完成后返回 PR URL、分支、HEAD、测试命令及结果、逐项需求证据、未完成项和必要部署待办。PR 达到可审状态后立即进入总控审核，不等待九个板块全部完成。
5. 总控逐 PR 进行静态差异审核、关键事务/身份/效果验证、旧版行为对照。发现问题立即回原任务修正；审核通过的准确 HEAD 立即登记并进入 `codex/v3-parity-integration`，使审核与后续开发并行。禁止把本地通过、排队成功、菜单存在或外部模拟成功称为生产完成。
6. `codex/v3-parity-integration` 由集成任务单一维护，持续吸收已审核提交；尽早创建以 main 为 base 的总集成 PR，使每次组合更新都运行现有 PR CI。各板块 PR 保留审查和证据入口，但不逐个合并 main、不逐个触发部署；已纳入总集成 PR 的个体 PR 在最终交付清单中标明替代关系。
7. 总集成 PR 持续执行跨板块接线、迁移顺序和联合验收。九板块达到本轮完成标准后冻结唯一发布候选 HEAD，提交准确候选、制品生成与校验步骤、迁移、配置、历史导入、风险、回滚和生产验收清单给用户；正式制品及真实历史dry-run属于部署阶段，按11文档记录。
8. 只有用户针对该具体发布候选明确确认上线后，才合并一次总集成 PR，并由 main 的现有工作流执行一次生产部署。该确认不由早期开发授权或本次流程调整自动推定。

## 4. 共同边界

- 每张表一个 Owner，跨领域只经稳定 Port 或版本化事件。沿用 Go 模块化单体、PostgreSQL 16、现有 River 与 External Effects，不另起队列/身份/重试框架。
- customers.id 是唯一业务客户主键；Provider 验证事实携带 kind/scope/assurance/source。Resolve 不建客；不猜测、不静默合并。缺少证据保持 unresolved/conflict。
- 必须原子的业务记录、幂等收据、审计、Outbox、任务/效果接受加入同一 UoW；网络调用在事务外。
- 企微写由 outbound 执行，支付写归 payment。纯 Provider 读不得伪装成外部写效果。unknown 禁止换键盲重试。
- 前端复用已有冻结 donor DOM/样式/交互；只在 V3 Host/Adapter 接入数据、认证、路由和错误。新建前端文件必须对应旧版确有而 V3 缺失的能力，并在 PR 列明。
- 历史导入用冻结、合成或脱敏测试快照；不连接旧库作运行回退。每条源记录有结果收据，重放不重复；历史终态不触发新效果。不得为了可归属而删除未解析记录。
- 自动测试只使用隔离 PostgreSQL、协议夹具和本地测试 Provider。不得把真实生产凭据注入测试进程。

## 5. 共享改动与依赖契约

- 回调入口先按解密后的 Event 分派独立严格解析器，保持现有外部联系人字段校验。08 主责现有回调快速接纳路径；09 复用该入口加 msgaudit_notify，不再改造普通入客语义。
- 01 主责 customer/wecom 同步逻辑，不改 08 正在处理的 callback 接纳文件。02 独占 survey；已有本地 customer 适配改动不擅自搬入。
- 03 主责 payment/order 结算及 product 普通购买；04 主责 coupon、现有 order 权益扩展和 service-period 产品叶子能力。共同文件先交总控确认负责人，禁止两方同时改同一契约。
- 付款人与受益人分开。03 提供可信已支付/已退款事实及稳定订单行标识；04 经 Owner Port 按来源订单幂等发放或调整权益。不把支付回调当作身份匹配器。
- 优惠券预占、订单金额快照须同事务；支付未知不释放；确认成功核销，确认关闭按旧规则释放。由 coupon 提供窄事务 Port，order 不读写 coupon 表。
- 共享 composition、OpenAPI、迁移编号和测试注册由集成任务或总控指定单一负责人协调。分支新增迁移先上报编号和语义；不得复制其他任务未部署迁移导致冲突。

## 6. 本轮不立项的治理

不建设新能力注册中心、通用事件平台、新监控产品、统一身份治理台、备份平台或整体部署重构。直接阻塞旧能力的缺陷在所属板块修复。完全尚未开发的额外降本方案需单列目标、收益、改动量与取舍，得到用户确认后才做。
