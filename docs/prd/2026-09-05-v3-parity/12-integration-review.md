## 工作区与输入

从固定基线 d6c216c4d9f8fe2197bb4abcdcfa9334cedde3a1 创建独立 clone 与 `codex/v3-parity-integration` 分支。该分支同一时刻仅由一位协调者维护；集成任务交接fa08f737后，根接手审核通过HEAD的纳入与文档记录，释放Sol槽位用于后续必要集成实现。不得把主工作区其他未提交业务代码带入；本目录总控 PRD、验收矩阵、部署待办和根目录已完成评估文档可按文件清单复制。

按验收矩阵核实每个 PR 的实际 HEAD、前置依赖及总控审核结果。只有审核通过的准确 HEAD 可以纳入；堆叠 PR 包含前置提交时只集成一次。总集成 PR 尽早以 main 为 base 创建并持续更新，使现有 PR 检查验证每个组合状态。不得合并主分支、推送 main、启用自动合并或调用 workflow_dispatch；部署 job 必须跳过。

每次纳入提交后更新验收矩阵，记录来源 PR、来源 HEAD、集成 HEAD、组合 CI 和未完成联合测试。组合失败时在原板块或明确的集成缺陷任务中修复，不在集成分支作无来源的业务改写。开发、总控审核和集成验证并行推进，避免把审查和冲突集中到最后。

## 客户同步基线缺口与已完成验证

以下d6基线问题已由PR142与PR145的真实PG/River测试补齐并审核纳入；最终装配持续回归，不能继续计为待开发。

Provider HTTP200 中 errcode=-1 为系统繁忙，按官方错误说明建议稍候重试且不超过3次。当前默认归为 provider_response_invalid 终态，需要在 Provider 读取的现有重试机制中实现有界恢复，不扩展到写操作。来源：https://developer.work.weixin.qq.com/document/path/90313 。结合既有token刷新策略验证权限/无效响应仍失败关闭。

联合01/08验证：客户未存在时欢迎语仍在期限内执行；重复回调和普通同步随后只形成一个客户根，保留正确员工关系，欢迎语发送标识不变。
