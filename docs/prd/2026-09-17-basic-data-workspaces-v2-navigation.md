# 基础多维表与指标看板 PRD · 页面层级修订稿

状态：用户于 2026-09-17 确认页面结构，并要求按飞书 UI 开发；正在实施，等待新版实际效果确认后上线。
本稿替代原 PRD 的页面组织、导航、视图设置及分享展示规则；原指标口径、领域所有权和授权约束继续有效。

## 1. 业务判断

用户有两种不同任务：进入页面查看业务汇总，或进入明细查找和处理具体记录。上一版将两类任务上下堆叠，造成首屏信息过重、明细位置过深、设置项混杂。

调整原则：一个业务入口，默认总览，通过顶部二级导航进入明细。保留成熟组件和已有业务能力，不增加复杂 BI 平台。

- OneID：本轮不执行身份操作；实现只读取既有 canonical customer 及领域 Port，不解析、建客、合并。
- Persistence：视图设置继续归各业务领域，以本地事务、CAS、幂等和审计保存；导航状态不引入新任务。
- External Effects：不增加 Provider 写入、同步器或队列；HXC 沿用原刷新任务。

## 2. 参考与方案判断

已核对现仓 `web/v3/materialLibraryPresentation.ts` 的 `mountMaterialLibraryTabs` 实现：素材库通过内容区顶部的图片／附件／小程序导航切换，使用 `/admin/materials?tab=...` 和当前页标记。复用其位置、选中态、间距及可访问性规范，不新增第二套左侧导航。

GitHub 参考：[Metabase dashboard interactivity](https://github.com/metabase/metabase/blob/master/docs/dashboards/interactive.md) 支持从汇总卡片跳到目标页面并传递筛选值。这里只借鉴“汇总到明细”的导航方式，不引入其平台或复杂自定义跳转编辑器。

方案比较：

| 方案 | 判断 |
| --- | --- |
| 顶部二级导航：数据总览／明细视图 | 推荐。与素材库一致，入口清晰，两页可独立直达 |
| 新增左侧树形菜单 | 能拆开页面，但增加导航层级，与现有素材库模式不一致 |
| 同页下方表格或折叠表格 | 改动小，但仍是纵向堆叠，不满足此次反馈 |

## 3. 页面层级与默认入口

```text
周期商品管理 → 选定商品 → 会员数据
                          ├─ 数据总览（默认）
                          └─ 明细视图

漏斗／数据看板
  ├─ 数据总览（默认）
  └─ 明细视图
```

这里的“首页”是各数据集工作区的默认页，不是 CRM 经营总览。周期商品总览仍限于选定商品，不扩大成跨商品报表。

- 左侧保留既有入口；页头统一标题，二级导航位于内容区顶部，位置与素材库一致。
- 点击业务默认入口进入数据总览；直接打开明细地址、刷新或前进／后退，保留对应子页。
- 二级导航是独立内容页面，不是锚点滚动、折叠区或弹窗。
- 示意路由：HXC 使用 `?tab=overview|details`；周期商品保留原商品参数并增加 `tab`。旧链接缺少 `tab` 时进入总览，保留商品及保存视图信息。
- 保存视图与页面类型是不同概念：“数据总览／明细视图”负责选页面，“默认视图／已保存视图”负责选数据范围和展示方案。

## 4. 数据总览

```text
工作区标题                         [刷新] [配置看板] [保存视图] [分享]
[数据总览 ●]  [明细视图]
[默认视图 ▾]  当前范围：……                         [筛选]

[总人数]  [有效会员]  [到期人数]  [其他所选指标]
[预设分布图]                       [预设分布图]
统计时间／数据新鲜度
```

- 首页只展示所选指标卡和图表，不渲染明细表、分页、表格列设置、分组和排序工具。
- 指标与图表沿用原口径，固定图表类型。配置看板通过侧面板选择显示项、顺序；保存后成为当前保存视图的一部分。
- 筛选入口集中，已生效条件显示为可编辑条件项；不将全部原始字段输入框铺满首页。
- 默认展示业务指标，OneID 质量及技术来源信息不进入总览正文。统计时间和未知状态保留，用业务可读文字呈现。
- 指标卡可提供明确的“查看明细”入口：进入明细页，并将卡片对应条件与当前条件取交集。只支持有明确明细谓词的预设指标，不建设通用钻取配置器。
- HXC 三类人群仍叫当前阶段分布，不宣称历史转化率；不新增时间趋势或不存在的时间筛选。
- “刷新”更新当前读取结果。HXC 原有触发同步任务的动作保留独立明确名称（如“同步数据”），不与刷新页面混淆。

## 5. 明细视图

```text
工作区标题                               [刷新] [保存视图] [分享]
[数据总览]  [明细视图 ●]
[默认视图 ▾]  当前范围：……
[查找] [筛选] [分组] [排序] [列设置]
[已生效条件……]                              共 N 人

┌─────────────────────────────────────────────────────┐
│ 会员／业务字段……                                    │
│ 分组标题＋全量组人数；可折叠                          │
│ 记录行……                                            │
└─────────────────────────────────────────────────────┘
[上一页] [下一页]
```

- 页面主体直接是明细表，不重复放一整组指标卡或图表。
- 查找、筛选、分组、排序和列设置集中在工具栏；现有业务编辑仅按既有授权开放。
- 表格获得主要可视空间。手机端工具栏换行／收纳、表格横向滚动；不让整页产生横向溢出。
- 内部身份质量信息仅通过明细页的“更多／内部诊断”查看，按现有权限控制，不增加第三个常驻子页。
- Product 维持两级分组，HXC 维持单级分组及字段白名单；全量过滤、统计、排序后分页的规则不变。

## 6. 范围联动与保存逻辑

一份保存视图包含三部分：共用查询条件、总览展示配置、明细展示配置。两页不各自维护一份同名但口径不同的查询。

| 操作 | 行为 |
| --- | --- |
| 普通切换总览／明细 | 保留数据集、当前保存视图与已提交条件；不丢失尚未保存的配置 |
| 修改筛选并应用 | 改变共用查询范围，两页随后都按该范围读取；明细游标失效并从首页开始 |
| 修改表格分组／排序／列 | 只改变明细展示，不改变总览指标口径 |
| 配置指标和图表 | 只改变总览展示，不改变明细字段和查询条件 |
| 点击指标“查看明细” | 共用范围 AND 指标条件；显示“来自：有效会员”等条件项，不静默覆盖既有筛选 |
| 返回总览 | 保留当前生效范围，指标与明细仍一致；可清除指标附加条件返回原范围 |
| 保存视图 | 一次保存共用条件和两页配置；有修改则明确显示未保存；并发覆盖反馈冲突 |
| 切换另一保存视图 | 有未保存修改时给保存／放弃／取消选项，不静默丢失；两页一起切换 |
| 默认进入工作区 | 恢复仍有权访问的上次已选择保存视图，否则使用系统默认；默认展示总览 |
| 刷新或直达链接 | 恢复子页、已有保存视图及可恢复配置；临时敏感条件不明文写入 URL |

旧保存视图仍可读取：原查询、分组、排序、列配置用于明细；原指标选择和顺序用于总览；缺失配置使用默认值。只做导航拆分时不强制新建业务表。

数字一致性以相同范围和数据版本为前提。若切换期间快照已更新，提示数据已更新并重新查询；不得用旧指标配新明细而不提示。查询失败保留上一成功结果并标注状态，陈旧响应仍不得覆盖新条件。

## 7. 外部只读分享

- 新公共链接默认进入数据总览，采用相同“总览／明细”的内容组织，但没有后台侧栏或管理动作。
- 仅指标链接只展示总览，既不显示明细导航，也不能通过改 URL／直接调 API 获得明细。
- 指标＋脱敏明细链接显示两个子页；明细单独展示，不堆在指标下面。
- 访客附加筛选只能进一步缩小授权范围；页面切换、指标跳转和查询都受服务端冻结范围与字段白名单约束。
- 公共“显示项”只改变访客当前呈现，不允许修改分享授权或保存内部视图。仅指标模式不提供跳转明细。
- 撤销、轮换立即阻断后续数据请求，旧 Product 分享合同保持不变。已签发的新策略链接不因本次改布局而扩权。

## 8. 后续实现范围及验收

已授权实施：拆分共享看板和表格的挂载职责；分别接入两个业务 Host 的子页导航；解耦两页设置；调整公共分享页面；重跑受影响旅程。

本轮不新增统计指标、公式、透视表、任意 SQL、跨表关联、历史趋势、拖拽设计器或独立 BI 服务。

必须新增／调整的验收：

1. 默认打开总览，不存在页面下方的明细表；切到明细后没有重复看板。
2. 二级导航位置和选中态与素材库一致；直达、刷新、后退和手机端操作正确。
3. 相同条件与版本下总览人数等于明细全量匹配数，分组人数不冒充当前页人数。
4. 指标跳转条件可见、可撤回，且只能在当前范围中缩小结果；没有关联明细的指标不伪造跳转。
5. 保存视图恢复两页配置；旧视图兼容；未保存提示、冲突反馈、IME、乱序、失败重试与失效游标不回归。
6. 仅指标分享不能绕过授权访问明细；明细链接不泄露隐藏字段；撤销与轮换验收继续覆盖两个子页。
7. 当前 PR 的旧 CI 仅证明旧布局。后续代码变更需重新执行 fast、必要的 compile／专项、真实 Host Chromium 和当前提交完整 CI；部署回读单独验证。
