# ADR-0008：企微侧边栏三元组上下文与精简 Customer 360

状态：Accepted（2026-09-04）

## 决策

侧边栏以系统配置的 `corp_id`、已认证员工 Session 的 `employee_id`、当前企微 JSSDK 返回的 `external_userid` 建立上下文。服务端以带企业 scope 的企微外部联系人身份调用 OneID `Resolve`，只允许解析到既有 canonical `customers.id`；不隐式建客，不查询、保存或验证员工与客户的跟进关系。

Context Token 只绑定 `corp_id + employee_id + customer_id + exp`。本模块不包含 relationship version，也不因关系表缺行、停用或删除而拒绝已认证上下文。全局企微 callback 和关系投影继续由原模块维护，不在本次删除。

侧边栏只提供核心画像（含安全时间线）、问卷、商品、订单、优惠券、素材六个一级页签。Customer 360 只聚合安全身份摘要、基础档案、订单统计、问卷统计、风险和最近触点。两者均不读取聊天、标签、跟进成员、运营状态或自动化状态；风险只使用上述保留领域的本地事实。

## 架构门禁

```text
OneID: resolves scoped WeCom external identity to canonical customers.id; no follow-relationship coordination
Persistence: local transactions + existing Provider-read infrastructure + outbound-owned Provider writes
```

业务写、幂等收据、审计、Outbox 和 External Effect 接受必须处于同一 PostgreSQL UoW。浏览器只使用短期一次性 grant 执行现有 JSSDK；accepted、client_executed、outcome_unknown、final_failed 分开持久化。未消费 grant 由 River 持久任务关闭，且明确记录没有服务端 Provider 调用。

## 后果

- Sidebar 只依赖 Customer、Identity、Survey、Product、Order、Coupon、Media、Radar、Outbound 的稳定 Port。
- 页面建立 Context 后不再传递 raw `external_userid`。
- Customer 360 读失败按分区降级，不触发 Provider。
- 旧 owners/tags/chat 接口若有其他调用者可继续存在，但本模块的路由响应和活动前端不消费它们。
