```sql
SELECT id,status,discovered_count,activated_count,already_linked_count,
       conflict_count,terminal_failed_count,projected_count,stale_count
FROM wecom_customer_sync_runs WHERE id = :run_id;

SELECT
  discovered_count = activated_count + already_linked_count + conflict_count + terminal_failed_count AS receipt_identity_ok,
  projected_count = activated_count + already_linked_count AS projection_identity_ok

SELECT count(*) AS duplicate_active_identity_keys FROM (
  SELECT kind,scope_key,normalized_value FROM customer_identities
  WHERE status='active' GROUP BY kind,scope_key,normalized_value HAVING count(*)>1

```

## 3. 源环境只读检查与快照

先使用受限账号连接 `150.158.82.186`，只做 schema 发现；不更新任何源表。具体数据库名、表名和列名必须以现场只读检查为准，不从会员表推测身份真相。

发现阶段必须确认：

- 源记录有稳定 `source_row_id`、企业 `corp_id`、`external_userid`、`phone`、`source_updated_at`。
- `(corp_id, external_userid)` 空值数、重复数和总数。
- 手机号空值、格式分布、一号多 external identity 数量。
- 快照的输出行数等于选定源范围行数。

快照必须严格包含下列六列，不得附带姓名、会员权益、问卷或其他业务字段：

```text
schema_version,source_row_id,corp_id,external_userid,phone,source_updated_at
```

`schema_version` 固定为 `phone-identity-import/v1`。导出后在受控目录计算 SHA-256，快照权限必须为仅当前运维用户可读。

## 4. 导入顺序

```bash
./migrate-phone-identities --mode inspect --input /secure/snapshot.jsonl --manifest-sha256 "$SNAPSHOT_SHA256" --corp-id "$WECOM_CORP_ID"
./migrate-phone-identities --mode dry-run --input /secure/snapshot.jsonl --manifest-sha256 "$SNAPSHOT_SHA256" --corp-id "$WECOM_CORP_ID"
./migrate-phone-identities --mode apply --confirm-apply --input /secure/snapshot.jsonl --manifest-sha256 "$SNAPSHOT_SHA256" --corp-id "$WECOM_CORP_ID" --run-key "$IMPORT_RUN_KEY"
./migrate-phone-identities --mode reconcile --run-key "$IMPORT_RUN_KEY"
```

命令只输出 run ID 和聚合计数，不输出手机号或 external_userid。任意一步失败必须停止，不跳过 dry-run/reconcile。

对账必须满足：

```text
input = attached + already_linked + conflict + unresolved + invalid + duplicate_input
```

完成后对受控样本执行 UI 脱敏值和审计揭示抽验。确认对账和回滚演练证据后，使用组织批准的安全删除流程删除明文快照，撤销临时访问。

## 5. 回滚演练

```bash
./migrate-phone-identities --mode rollback --confirm-rollback --run-key "$IMPORT_RUN_KEY"
```

回滚仅 CAS 退役本 run 新建且仍由 `phone_import` 拥有的 declared phone，并同事务刷新 Customer 目录脱敏投影。它不硬删历史、不退役既有手机号、不影响 verified identity。
