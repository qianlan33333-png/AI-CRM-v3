# 交易与历史用户数据生产迁移 Runbook

## 1. 安全边界

- Provider 开关保持 disabled，历史终态不得创建 External Effect。
- 源库只读；目标写入只通过 `cmd/migrate-commerce-history` 和各领域 Port。
- 快照 `0600`、不入 Git；日志只输出行数、金额、digest 和安全错误码。
- 任何源覆盖缺失、manifest 漂移、OneID scope 未确认或对账不等时立即停止。

## 2. 全量快照

规范化文件必须使用 `aicrm-commerce-history-v2`，并包含六个为真的 coverage 位：identities、wechat_pay_orders、wechat_pay_refunds、wechat_shop_orders、wechat_shop_refunds、alipay_orders。

```bash
bin/migrate-commerce-history --mode=inspect --snapshot=/secure/commerce-v2.json
bin/migrate-commerce-history --mode=dry-run --snapshot=/secure/commerce-v2.json
sha256sum /secure/commerce-v2.json
```

`inspect` 可用于检查不完整快照；`dry-run` 和 `apply` 对任何缺失覆盖失败关闭。

## 3. 导入

先做源备份和目标备份，记录 T0 水位。对已确认 digest 执行：

```bash
AICRM_DATABASE_URL_FILE=/etc/aicrm/database_url \
bin/migrate-commerce-history \
  --mode=apply \
  --snapshot=/secure/commerce-v2.json \
  --manifest-sha256=<confirmed-sha256> \
  --confirm-apply
```

同一 `run_key + manifest digest` 可安全重放；同 run key 的 digest/schema 漂移必须报冲突。身份先经 Provider History Adapter 构造 verified fact，再走 OneID 显式 provision；订单和支付/退款分别走 Order、Payment Port。

## 4. 增量追平与停写

1. 以 `(updated_at, source_pk)` 导出 T0-T1 delta，生成新的完整 manifest 和独立 run key。
2. 在批准窗口关闭旧交易写入口；确认无在途 Provider callback。
3. 导出最终 delta 并重复 inspect、dry-run、apply。
4. 禁止 v2/v3 双主写；写路由切换前 Provider 开关仍保持 disabled。

## 5. 对账

```bash
AICRM_DATABASE_URL_FILE=/etc/aicrm/database_url \
bin/migrate-commerce-history \
  --mode=reconcile \
  --snapshot=/secure/commerce-v2.json \
  --manifest-sha256=<confirmed-sha256>
```

对账按当前 run 的 receipt 集合检查：全部身份可由 OneID 精确解析；输入数和完成数相等；订单、支付、退款笔数相等；订单金额和退款金额相等。成功后 run 才标记 `reconciled`。

随后按 Provider/状态/自然日抽样源库、manifest、v3 API 与管理页四点一致。任一不等时保持旧读路由，不启用 Provider。

## 6. 上线与回退

- 先切交易读取并观察；再在单独审批后配置 WeChat Pay/WeChat Shop 凭证和回调域名，最后启用写入。
- `accepted/queued/executed` 不等于支付或退款成功；仅验证回调或主动查询可形成终态。
- 迁移回退不硬删审计、receipt 或冲突事实。已被 v3 新交易引用的根不得自动回滚。
- 出现身份错误归属、重复退款、Provider outcome unknown 被换键重试、权限绕过、PII 泄漏或静默丢行时立即关写并进入人工处置。
