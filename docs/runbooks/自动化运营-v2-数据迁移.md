# 自动化运营 v2 数据迁移 Runbook

## 1. 边界与停止条件

- 供体固定为 `AI-CRM-v2@6bfbe5816bb89913c70adaca87d6a486260e016e`，源凭据必须是只读账号。
- Provider 在迁移、Shadow 和切流前保持 disabled；旧运行和效果仅封存为不可重放历史，迁移不得创建 River job 或 EER effect。
- v2 `customer_id` 不是 v3 OneID。成员只能用源快照中 namespace 完整的 verified identity，通过 v3 Identity Port 解析为 canonical `customers.id`。
- 无命中、跨根命中、非法 scope 分别进入 `unresolved`、`conflict`、`invalid`；不建客、不绑身份、不自动合并。
- 源库存在 `enrolled`、`queued` 或 `outcome_unknown`，源凭据可写，manifest 漂移、计数等式不成立、目标没有指定的 active 管理员，立即停止。
- 加密快照和密钥均为 `0600`，不得进入 Git；数据库 URL 只从环境变量读取，不放在命令参数或日志中。

## 2. 只读盘点与冻结

先停止 v2 自动化运营写入口并完成在途效果对账，再使用只读账号：

```bash
export AICRM_V2_AUTOMATION_DATABASE_URL='<read-only source DSN>'
bin/migrate-automation-operations inspect \
  --source-system ai-crm-v2-production
```

盘点必须确认：schema allowlist 完整、`writable_credential=false`、active enrollment/action 和 `outcome_unknown` 均为零。该命令不输出外部身份和数据库 URL。

## 3. 加密快照

```bash
umask 077
bin/migrate-automation-operations keygen \
  --key-file /secure/aicrm-automation-operations.key
bin/migrate-automation-operations extract \
  --source-system ai-crm-v2-production \
  --snapshot-file /secure/aicrm-automation-operations.snapshot.enc \
  --key-file /secure/aicrm-automation-operations.key
bin/migrate-automation-operations validate \
  --snapshot-file /secure/aicrm-automation-operations.snapshot.enc \
  --key-file /secure/aicrm-automation-operations.key
```

快照使用 AES-256-GCM 鉴权加密，包含迁移所需身份值，因此只能在受控主机保存。输出文件已存在时命令拒绝覆盖。

## 4. 目标 dry-run 与导入

先对 v3 执行平台 migration，再选择一个 active 管理员 ID 作为迁移 actor。所有源 active 配置都会以 paused 导入。

```bash
export AICRM_DATABASE_URL='<target DSN>'
bin/migrate-automation-operations dry-run \
  --actor-id <active-admin-id> \
  --snapshot-file /secure/aicrm-automation-operations.snapshot.enc \
  --key-file /secure/aicrm-automation-operations.key

bin/migrate-automation-operations apply \
  --actor-id <active-admin-id> \
  --snapshot-file /secure/aicrm-automation-operations.snapshot.enc \
  --key-file /secure/aicrm-automation-operations.key \
  --confirm-import
```

每个 logical table 必须满足：

`source = imported + duplicate + mapped + unresolved + conflict + invalid + quarantine`

人工确认每个身份桶和发送人隔离桶后，使用同一加密快照做完整重放：

```bash
bin/migrate-automation-operations replay-check \
  --actor-id <active-admin-id> \
  --snapshot-file /secure/aicrm-automation-operations.snapshot.enc \
  --key-file /secure/aicrm-automation-operations.key
```

重放必须零新增且 `provider_effects_created=0`、`river_jobs_created=0`。

## 5. 对账与回退

apply 输出稳定 `batch_key`。用该键完成目标对账：

```bash
bin/migrate-automation-operations reconcile --batch-key <batch-key>
```

只有计数恒等式成立、导入事务前后 EER/River 计数相等，batch 才能进入 `reconciled`。历史运行不生成当前 Automation run/enrollment。

回退为非破坏性操作，只暂停导入的人群包并保留快照、source map、quarantine 和历史审计：

```bash
bin/migrate-automation-operations rollback \
  --batch-key <batch-key> \
  --confirm-rollback
```

任何已激活的导入包都会阻止回退；不得手工删除迁移证据。

## 6. Shadow 与切流前验收

- 在同一 reference time 比较 v2/v3 配置摘要、源成员数、mapped/unresolved/conflict/invalid/quarantine 合计及 v3 published member digest。
- v2 写入冻结后只能生成一次最终全量加密快照；禁止双主写。
- 逐包补齐或重建不兼容的 v2 定义，确认 Agent published digest、素材、sender eligibility 与生产策略后人工激活。
- Provider 探针必须使用单收件人、已授权固定话术和新幂等键；以 Provider receipt 与 EER reconciliation 为成功证据。
