# Route-gap triage for the 16 static candidates

候选版本：`dcfc02290daca3f4bb9509120698e9e976b5369b`。本次只读核对矩阵中的 13 个 `mounted_no_text_reference`、2 个 `route_clue_without_mount` 和 1 个 `mount_not_found_by_static_scan`。结论来自实际 Go handler、Composition Root/wrapper 和已有测试代码；没有运行生产操作，也没有把测试代码中的断言当作本次候选已经执行的收据。

结论分为三类：

- `静态误报`：矩阵的字符串扫描漏掉了常量、构造路径或 wrapper，但实际挂载和具体测试存在。
- `真实 route-level 缺口`：实际 handler 已挂载，已有服务层或相邻接口测试，但没有该 method+path 的 HTTP 测试。
- `挂载/文档不一致`：handler 或文档路径存在，但当前 Composition Root 没有把候选路径接到该 handler；需要决定补挂载还是修正文档。

## 收敛结论

- 1 项（G01）是明确静态误报：常量路径实际挂载且已有直接测试。
- 4 项 acquisition link（G04-G07）是常量拼接导致的扫描漏报。GET 与 reconcile 有直接测试，PATCH 只有 malformed-body 断言，DELETE 没有具体 HTTP 测试。
- 9 项（G02-G03、G08-G14）实际 handler 已挂载，但缺少各自 method+path 的 HTTP contract 测试；服务层、存储层或通用鉴权测试不能代替这些 route-level 证据。
- 2 项（G15-G16）是挂载/文档不一致，不能归类为单纯“未找到测试”。其中 G15 有实现分支但 Composition Root 缺前缀，G16 的 OpenAPI 路径与已挂载 canonical webhook 完全不同。

本报告没有把任何一项标记为 release pass，也没有修改业务代码或矩阵生成规则。后续补测应绑定候选 SHA，并分别保留 HTTP response、数据库状态和 provider/reconciliation 收据。
