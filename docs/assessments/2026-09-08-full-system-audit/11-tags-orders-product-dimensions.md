# 标签真实执行、订单查询与商品维度（2026-09-08）

状态：用户追加本轮必修。候选实现与线上版本分别验收，尚未形成线上通过结论。

## 用户要求与完成条件

1. 标签管理新增、改名、删除须实际作用于企业微信。复用既有 Outbound / External Effects 执行链，并回读官方标签目录。仅本地记录变化或成功提示不算完成；待执行、失败、结果不明应显示真实状态，不能盲目重试。
2. 订单创建时间统一显示北京时间 `YYYY-MM-DD HH:mm:ss`，不展示时区后缀或毫秒；正确转换时间，不能直接删掉原始时间的 Z。
3. 订单支持手机号及外部联系人 ID 的服务端跨页查询；隐藏内部付款身份（例如 customer:123），保留可识别的付款人姓名。查询仅解析已有归属，不建客、不合并。
4. 普通商品与周期商品编辑均只显示当前维度；左侧切换后右侧进入对应内容，切换不丢失草稿。
5. 购买后动作复用标准版交互：启用开关、展示引流二维码 / 支付完成直接跳转单选，只展示当前选项需要的配置。
6. 企微标签与外部推送分别有启用开关，标签采用统一标准选择器，推送采用标准版字段与操作。开关保存、重新打开回显及实际消费者使用一致；关闭后不得执行外部动作。

## 分类

- OneID：订单查找与客户打标读取规范客户根及稳定 Customer / Identity Port，不新增身份匹配系统。商品表单展示本身不涉及身份。
- 持久化：商品配置为所属领域事务和版本校验；切换维度草稿保留不是服务端保存。
- Provider 读取：企微目录回读使用现有读取适配器，网络调用不持有数据库事务。
- Provider 写入：标签修改与付款后动作继续复用既有领域意图、Outbound / External Effects；不增加新队列或重试状态机。

## 验收

- 使用授权测试标签完成创建、改名、删除及企微回读；客户打标与去标只针对已授权测试客户。
- 订单搜索命中当前页之外记录；手机号 / 外部联系人 ID 不匹配时为空，不退化为全部订单。时间包含跨 UTC 日期边界用例。
- 两类商品每个维度来回切换、保存、重新打开；分别验证功能关闭、二维码模式、跳转模式，以及标签与推送的启用状态和配置回读。
- 所有真实付款与退款仍沿用三笔小额订单验收方案，不对真实商品配置或真实外推目标进行试错。

## 候选实现与本地证据

- 订单手机号与外部联系人查询已接 Identity Port，仅解析现有可信客户；无匹配返回空列表。身份筛选时暂禁止导出，避免导出未筛选的全部订单。北京时间格式已通过非北京时间浏览器环境下的重复渲染测试。
- 付款确认在原 Order 事务内冻结商品动作，通过既有 Customer 标签命令与 External Effects 提交打标意图。二维码/跳转、标签开关相互独立；缺渠道或不安全跳转在配置创建/编辑时拒绝。0117 专用 PostgreSQL 回归覆盖旧商品、空标签数组、标签单独启用、事件重放和事务回滚。
- H5 付款完成页已消费冻结动作，并保留终态订单记录；本地实际脚本测试覆盖二维码刷新、跳转失败后刷新，不重复创建订单或唤起支付。
- 标签目录写入增加独立部署开关，默认关闭；未开启时明确返回 `tag_catalog_write_unavailable`，不降级为本地增删。执行需要有效企微通讯录凭据、Outbound 开关、目录读取授权、目录写入授权，以及 API / effects-worker 加载相同配置。配置中心尚无该窄写入开关的投影。
- 上述是候选代码与本地验证；真实企业微信目录变更、小额支付、退款及部署后的页面验收仍未通过，不能标记线上完成。
