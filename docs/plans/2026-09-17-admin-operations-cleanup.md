# 运营后台精简与统一用户编号 PRD

## 业务判断

运营页面只展示运营决策所需信息，删除重复标题、空提示和内部执行细节；配置与业务能力必须具有真实持久化和运行消费者。保留现有标准页面结构，不进行视觉重设计。

OneID: reads canonical customer / provisions customer。客户表仍是唯一客户根，七位业务编号由 Identity 领域持久生成并唯一约束；不能使用字符串补零，也不能重写已有客户主键、外键或身份归属。旧数字 ID / CID 链接继续解析到原客户，新编号的展示、搜索与详情导航必须统一。
Persistence: stateless（展示精简）、local transaction（编号及素材分组）、Provider read（员工昵称刷新）。员工通过 WeCom 读取 Adapter 和 Access Port 更新，不改变现有权限。大模型凭据需要受保护的存储及实际配置消费者，禁止仅做可保存的空界面。没有新增 Provider 写入、身份匹配器或任务队列。

## 范围与验收

1. 交易列表删除订单号下的重复支付渠道和“非分销订单”；保留真实分销信息、金额、状态和详情操作。
2. 共享后台内容页头仅显示模块标题，删除“用户管理后台”及其面包屑；既有页面动作保持可用。
3. 退出测评问卷目标创建及执行能力；普通问卷、提交、支付与完成动作不受影响。删除前检查持久化数据及引用，不静默删除历史提交。
4. 素材图片、附件、小程序均不展示刷新诊断和进度明细；普通刷新可用。按素材组别筛选，包含全部、未分组和具体组别；分组保存后刷新仍有效。
5. 员工列表使用 Provider 返回的真实姓名/昵称，未知时不伪造“企微客服”前缀；刷新读取 Provider 最新明细并更新已有员工，不创建登录授权。移除开通权限入口。
6. 配置中心保留真实运营连接配置（企微、后台访问、微信支付、小店、公众号等），移除平台内部参数与不支持的占位。单列大模型设置，服务商、模型、API Key 为主，保存与运行读取一致，密钥不明文回显。
7. 问号支持鼠标悬停和键盘聚焦，提示简短且对应实际状态原因。
8. 七位编号由数据库持久分配，唯一且并发安全；旧客户补充编号而非换根。用户列表、档案、订单、侧边栏、查询与详情导航覆盖同一映射，无空值、无错归属。
9. 用户档案移除标签草稿、风险摘要和同步元信息；复用侧边栏 360 触点语义；订单含商品名及直接详情入口。

## 交付验证

逐项覆盖正常、空数据、失败、刷新和旧链接兼容；涉及编号生成需验证并发唯一、回填完整、搜索和所有消费者一致；员工 Provider 读取失败不能覆盖已有可信昵称。先 fast、Go compile 和专项测试，再以最终提交运行完整 CI。合并 main 后按已有 SSH 发布流程部署，分别记录构建、部署、认证页面读回与 Provider 读取证据。

## V3 运营接口增量

冻结供体 OpenAPI 保持不变。V3 新增接口：图片列表支持 `only_ungrouped=true`；`GET /api/admin/config/ai-model` 返回 provider/model/configured/version；PUT 接收 provider/model/api_key/expected_version，要求管理员、CSRF 和版本匹配，密钥 AES-GCM 加密，审计仅记录操作者及版本，更换厂商必须提供新密钥。`POST /api/admin/access/users/refresh-names` 读取企微后，在一个事务内更新已有员工昵称并审计。模型配置保留自动化及 External Effects 门禁，已冻结任务不能静默更换模型。

附件、小程序使用各自库的 `GET /groups` 与 `PUT /{id}/group`，保存带版本和幂等键；列表 `category` 缺省表示全部，空字符串表示未分组。迁移 0178 回填稳定七位编号，0179 存储加密模型配置，0180 持久化素材组别。模型密钥使用现有稳定数据密钥的独立 HMAC 派生密钥加密，不在响应中回显；运行消费者仍遵守既有启用和外部效果门禁。

## 当前本地验证边界

PostgreSQL 专项已覆盖编号回填及并发分配、素材分组筛选/重放/版本冲突、员工昵称刷新、模型配置加密/重启读取/权限。页面专项已覆盖普通问卷编辑、商品和订单既有操作、档案订单链接、分组、共享标题清理。真实 Chrome 运行 Access 治理与标签选择旅程；本机 Chrome 不等同于 GitHub Linux Chromium，最终交付以提交对应的完整 CI 为准。
