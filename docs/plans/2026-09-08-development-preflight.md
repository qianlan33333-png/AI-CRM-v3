# 开发检查前置与浏览器必跑收口

## 范围与分类

OneID：不涉及，本次只修改开发工具和 CI 编排，不读写客户身份。
Persistence：stateless，不修改业务事务、任务或数据库结构。
External Effects：不涉及，不修改 Provider、生产参数或部署动作。

复用现有架构、供体冻结、去重、PostgreSQL、race、浏览器和发布打包检查。
不改业务默认配置、不重写测试夹具、不删断言；并行业务 PR 继续在自己的分支收口。

## 提交前顺序

1. 运行 `python3 scripts/dev_preflight.py fast`：格式、架构/身份边界、工作区差异、源码视图、PR01 冻结字节与检查器自身测试。无需 npm 安装、外部供体检出、数据库或浏览器。
2. 运行 `python3 scripts/dev_preflight.py compile`：所有 Go 包及测试编译，复用现有供体视图入口；这一步不是业务测试通过。
3. 用独立 PostgreSQL 16 测试库重现原失败用例，并执行受影响领域、Composition 与 race 测试。不得指向生产库；不得用跳过数据库用例的结果作为通过证据。
4. UI 变更按现有固定工具版本、两个冻结供体和 `scripts/run-donor-view-consumers.sh check` 构建最终 Host/暂存产物，再运行 `python3 scripts/dev_preflight.py browser`。macOS 无法启动 Chromium 时，明确保留 Linux CI 验证项。
5. 本地专项通过后提交 PR，完整 Linux CI 是最终门禁。刷新准确 HEAD 后再审核；改动后旧 HEAD 的绿灯不能继承。

每次预检打印证据目录，包含 HEAD、工作区状态、命令、耗时、退出码和日志；可用 `--report-dir` 指定目录。证据不要提交为源码。默认写系统临时目录，不自动记录环境变量或凭据；日志仍应遵守现有测试脱敏规范。

`fast` 只验证列出的快速项：完整冻结合同（含 20 个逻辑文件）、去重基线比较、全部领域和业务测试仍在 CI 必跑。去重检查读取提交对象，所以最终证据必须对应已提交 HEAD；本地工作区状态不会被冒充为准确提交验证。

## CI 调整

- `preflight` 在数据库服务和前端依赖安装前完成快速检查、原去重门禁、全包测试编译。
- 官方 SDK ABI 验证独立运行，与 preflight 并行，不占用数据库验证时间。
- `integration` 依赖两者成功，再运行原前端、真实 PostgreSQL、浏览器和 race 检查。共享测试库的包保持串行。
- 保留原必需状态 `check` 为汇总门禁：任何前置失败、取消或跳过均失败。保留原部署条件，部署仍依赖完整 `check`；不增加 paths 过滤或允许失败设置。
- 去重针对实际检出的 PR 合并提交与目标基线比较，保留祖先要求，避免把更新后的 main 与非其后代的分支 HEAD 错配。

没有为了拆分而在多个重型任务中重复安装前端和构建暂存包。此轮不承诺完整 CI 固定缩短多少分钟；实际收益用快速失败阶段耗时、首次完整 CI 通过率和返工轮数核算。

## 浏览器集合与验收

所有位于 `cmd/aicrm`、命名为 `Test…ChromiumJourney` 的真实 Host 旅程，经 `go test -list` 从编译后的测试包发现。两条壳旅程先跑，其他业务旅程自动全部加入后续阶段，不再逐 PR 修改工作流正则。其他命名或其他包不在这个自动发现约定中，新增时须明确接入。

既有七条旅程作为最低覆盖要求保留。结果读取 `go test -json`，每条所选顶层测试必须实际 pass，子测试 skip/fail、缺终态、空集合或包失败均拒绝，不能用命令返回零替代执行证据。

验收包括：新增问卷/群运营式测试自动加入、两组无重复且完整、移除既有测试被拒绝、缺失/跳过/中断结果被拒绝、真实通过被接受。保留原 PostgreSQL、race、SDK 和完整暂存包检查；并行板块 PR 新增旅程合并后会自动发现。

## 并发开发与回滚

共享 Composition 默认值修复由现有业务任务负责，本 PR 不触碰。其他分支若修改旧 Chromium 正则，合并时保留自动发现入口，其新增测试会自动纳入，不能恢复硬编码名单。

修复流程：先保存原失败名称与日志，单独重现并修复，再跑完整失败阶段，最后全量 CI。共享接线变化需要覆盖其他使用者；不反复推送试错，也不通过改断言或退出码掩盖问题。

本次只有工具/工作流/说明文件；回滚此 PR 即恢复原串行工作流，不涉及数据回滚。未合并前不改变主线发布流程。
