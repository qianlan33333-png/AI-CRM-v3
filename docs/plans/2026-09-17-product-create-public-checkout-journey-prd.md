# 商品创建与购买闭环修复 PRD

## 背景与问题

生产验收发现同一条普通商品链路存在五个相互关联的缺陷：新商品列表顺序与默认状态不符合运营预期；首次创建页仍展示退役的外部推送表单；没有页面素材的商品仍先展示空详情页；已支付订单虽然冻结了渠道二维码动作，但 Channel 当前配置清空二维码 URL 后，支付页不会读取仍有效的已验证二维码资产，最终显示“后续指引暂不可用”。

本次只修复上述行为，不新增商品能力、不改变外部推送协议、不重放历史支付或外部效果。

## 开发前判断

- OneID：读取既有支付会话和购买归属的逻辑保持不变。本次不解析、创建、绑定或合并外部身份，不新增 OneID 依赖。
- Persistence：商品创建、列表读取和渠道二维码读取属于现有 PostgreSQL 本地事务/只读投影。商品创建仍由 Product 的原有 Unit of Work 提交。
- External Effects：商品支付后外部推送仍复用既有 Product → Order → Outbound / External Effects 路径。本次不新增 Provider 写入、队列、Worker、重试或对账状态机；二维码回显只读取 Channel 已持久化且已验证的有效资产。
- 原子性：商品主体创建和外部推送配置仍是两个已有命令。首次创建页面在主体写入成功后取得真实商品 ID，再提交外推配置；若第二步失败，页面切换到该已创建商品的编辑地址，后续只重试配置，禁止重复创建商品。

## 参考实现

- PR #366 固化了支付下单时的购买后动作快照、旧版外推字段顺序和独立保存协议。本修复继续使用这些协议与同一套管理后台组件。
- PR #375 修复了渠道列表加载和商品创建冲突回读。本修复保留其单次创建与回读语义。
- Channel Catalog 现有汇总读模型已经把 runtime 二维码资产与 `legacy_verified_active` 历史资产识别为可用资产；公开支付指引应复用相同有效性规则，而不是只读当前配置字段。

## 目标行为

1. 普通商品列表按创建顺序倒排；刚创建的商品位于第一页第一项，游标和 offset 分页保持稳定、无重复。
2. 普通商品通过创建接口创建时默认 `enabled=true`、生命周期为 `enabled`。编辑、停用、归档和历史商品状态不变。
3. 已支付订单的二维码动作优先使用活动 Channel 当前配置中的 HTTPS 二维码；当前配置为空时，读取该 Channel 最新的、未退役且状态为 `executed` / `reconciled` 的运行时二维码资产，再回退到 `legacy_verified_active` 历史资产。其他状态、空 URL、非活动 Channel 均继续失败关闭。
4. 普通商品公开详情路径在没有任何有效页面素材时，保留合法推广上下文并直接重定向到支付路径；有素材时继续展示详情页。支付路径本身不循环重定向。
5. 新建商品和编辑商品使用完全相同的外部推送面板、字段顺序、开关和校验。新建页先保留本地配置草稿；首次保存商品后用返回的商品 ID 调用现有外推配置接口。外推保存失败时不得再次 POST 商品。

## 非目标

- 不修改外部推送 payload、幂等规则、执行状态或 Provider 调用。
- 不为缺失二维码的 Channel 自动调用企微生成资产。
- 不修改已支付订单冻结的动作模式、商品价格或购买归属。
- 不改问卷配置或问卷提交完成页。

## 验收

- Product store / app 测试证明倒序分页和创建默认启用。
- Channel PostgreSQL 测试证明公开二维码读取优先级、活动状态和失败关闭。
- Product public HTTP 测试证明零素材重定向、有素材保留详情、推广上下文保留。
- 前端测试证明新建路由挂载与编辑页一致的外推面板，首次保存只创建一次商品并随后保存完整外推配置；失败重试不会二次创建。
- 运行 `dev_preflight.py fast`、`compile`、受影响专项、完整 CI；合并后按生产发布脚本备份、安装并验证 readyz、服务进程、静态资源和只读业务状态。
