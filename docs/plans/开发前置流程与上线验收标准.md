# 新 CRM 开发前置流程与上线验收标准

## 适用范围与分类

适用于新功能、能力扩展、Bug 修复、调试、并行开发、合并和上线。本文自身：

```text
OneID：不涉及
Persistence：stateless
External Effects：不涉及
```

业务代码仍执行 `skills/aicrm-v3-development/SKILL.md` 的三轴分类。

## 新功能三步门禁

1. 市场/GitHub 调研：至少 2 个成熟方案和 1 个高质量 GitHub 参考；找不到时记录搜索范围、关键词、时间和结论。
2. 复用评估：检查已有领域、共享组件、标准组件、OneID、持久化、内部任务和 External Effects，记录采用、扩展、舍弃和新增理由。
3. 完整 PRD：包含用户、业务判断、成功标准、接口/数据/权限边界、架构分类、测试、上线、监控、回滚和并行依赖。

PRD 经用户确认后冻结；重大范围、合同或风险变化必须重新确认。

## 一次闭环交付

所有假设、PRD、复用方案和风险边界确认且用户明确开始开发后，执行者持续推进到完整上线验收，不把可由既定流程判断的常规选择逐步退回用户。只有新的业务决策、红线风险、凭据/权限缺失或部署证据不一致才暂停并报告。

完整终点为：实现 → 本地完整验证 → 预发布机 `49.232.57.128` 完整验收 → GitHub 轻量一致性门禁与合并 → 生产 SSH 部署 → 部署后认证读回 → 观察窗口验收 → 触发一次“彩纸礼炮”庆祝。未完成最后一项不得称为完成。

彩纸礼炮规则：只有版本、健康状态、认证读回、真实业务读回和观察窗口全部通过后，才调用 Codex 的 `mcp__codex_app__fire_confetti` 一次。构建成功、PR 合并、部署开始、服务启动或仅 `/readyz` 通过都不能触发；部署失败、回滚、结果未知或观察窗口未结束时不得触发。同一上线事件只触发一次，重复重试不得重复庆祝。

预发布使用与生产一致的系统、PostgreSQL 16、systemd 和发布目录，使用合成 CRM 数据完成迁移、健康、关键 API、真实 Chromium 旅程和回滚验收；不复制生产敏感数据。预发布成功后生成 SHA/tree 绑定 receipt。

GitHub PR 默认只检查当前 head/tree、最新 main、冲突、治理、secret scan、迁移编号和证据字段；运行时代码、迁移、发布包或前端页面变更还必须核对与当前 tree 绑定的预发布 receipt。纯 CI、治理、Skill 和文档变更不要求无意义的应用部署 receipt，也不重复本地长测试。完整云端 CI 仅由维护者通过 `workflow_dispatch` 并明确设置 `force_full=true` 执行。合并若生成新的 merge/squash SHA，必须比较 merge 后 tree 与预发布 tree；tree 不一致就重新预发布。

## 并行板块与冲突治理

每个工作项登记：

```text
工作项/板块、负责人、分支或 worktree、状态、修改范围、共享入口、依赖项、预计上线窗口
```

Composition、公共组件、迁移、CI、Provider 和部署脚本串行合并；普通领域可并行但必须在合并前同步最新 `main` 并重跑受影响测试。Debug 分支不能直接成为稳定依赖。

合并前填写：

```text
当前 main HEAD/tree：
活跃分支与 PR：
重叠文件/模块/迁移/API：
其他已合并但未部署版本：
当前排队上线版本：
正在执行的部署或观察窗口：
本次合并需要重新运行的测试：
```

存在部署未完成、部署后读回未完成、未知结果、回滚未完成、共享合同顺序依赖或过期 HEAD 时暂停并重新排队。

## 发布队列

已合并且完整验证的提交进入“待上线”；一次只执行一个生产部署。部署后独立验证版本、迁移、健康、管理员页面和真实业务读回；观察窗口无异常后才放行下一版本。CI 可简化编排和重复报告，但不能删除适用测试、真实验收、部署后读回或回滚准备。紧急热修必须由用户明确标注，并记录插队原因、回滚方案和补齐验证。

排队上线不等于已上线，部署成功不等于业务验收完成。

## Bug 修复流程

保存失败证据 → 判断根因和影响 → 先补回归测试/旅程 → 最小根因修复 → 执行原失败阶段和受影响全链路 → 输出防复发措施和未验证项。除非用户明确标注线上热修，否则走完整流程。

## 上线前测试矩阵

本地和预发布必须完成适用层级：静态/架构/敏感信息；编译/单元/race；PostgreSQL 16/迁移/事务；集成/权限/真实读回；前端 typecheck/build/组件合同；真实 `Test…ChromiumJourney`；OneID scope/verified/pending/conflict；External Effects 幂等/重放/回调/对账；发布包、Host Key、部署后读回、监控和回滚。GitHub 只保留一致性和治理证据门禁。

PR 只保留准确 HEAD/tree、并行与发布快照、测试摘要、证据目录和未验证项。作者声明只作为上下文，不作为独立上线门禁；门禁只保留当前 head/tree、预发布 receipt、治理安全检查和部署后读回。

## 合并标准

分支已同步最新 `main`；并行与发布快照完成；无冲突上线任务、未知部署或未结束观察窗口；本地适用测试和真实业务读回完成；PR 写明 OneID、Persistence、External Effects、前端复用和影响范围；不存在身份错误归属、重复外部效果、跨领域写表、静默丢数据或第二套执行/身份内核。

## 奥卡姆剃刀约束

优先复用已有能力，采用最小接口、最小改动和单一 Owner。新增队列、身份系统、组件体系、重试机制或发布流程，必须先证明现有能力无法满足。
