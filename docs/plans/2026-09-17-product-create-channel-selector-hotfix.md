# 商品创建与购买后渠道码紧急修复 PRD

## 业务判断

- OneID：不涉及。商品配置和渠道目录不解析或归属客户身份。
- Persistence：商品创建使用 Product 现有 PostgreSQL Unit of Work；渠道码为 Channel 当前目录只读；本修复不新增持久任务或 Provider 写入。
- External Effects：不涉及新的外部效果。选择已有渠道码只保存其稳定资源 ID，支付后的既有执行链保持不变。

## 已确认问题

1. 新建商品页已经读取渠道目录，但 V3 购买后动作适配层没有接收该目录，因此下拉框只有“不配置引流渠道码”。启用二维码模式并保存空渠道时，Product 契约正确拒绝为 400。
2. `product_code` 是唯一业务编码。重复编码创建正确返回 409，但页面只显示通用 HTTP 错误，用户无法知道应更换编码。

## 目标行为

1. 普通商品和周期商品的新建、编辑页均列出当前启用渠道码；已保存但后来停用或归档的渠道仍以“已选渠道”保留读回。
2. 启用“支付后展示引流二维码”时必须选择渠道码；缺少选择时不发请求，直接提示“请选择引流渠道码”。
3. 新建商品时，如果当前已加载目录中存在相同商品编码，直接提示编码已存在；若并发创建导致服务端返回 409，也显示同一业务提示，不自动覆盖旧商品。
4. 保存继续复用现有幂等键、版本控制和 Product UoW，不新增重试或第二套写链路。

## 验收

- 新建普通商品页的渠道下拉框显示启用渠道并可写入 `lead_channel_id`。
- QR 模式未选渠道不产生 Product POST。
- 重复编码不产生 Product POST；服务端并发 409 显示明确的重复编码提示。
- 唯一编码的新商品只创建一次，保存后进入带 ID 的编辑页。
