# 普通商品沉浸式详情与渐进加载 PRD

## 业务判断

- 有页面素材的普通商品，公开 `/p/:code` 页面只展示详情素材和底部价格/购买操作，不再展示商品名称或描述摘要卡片。
- 首张详情图在通过既有身份与购买资格检查后立即高优先级加载；其余图片只在接近视口时加载，避免长详情页一次请求全部素材。
- 任一公开接口请求必须在有限时间内成功或进入已有错误/重试状态，不能让身份核验页面永久等待。
- 无页面素材仍沿用 `/p/:code` 直接跳转 `/pay/:code` 的既有规则；支付页、支付幂等、购买后动作均不改变。

## 参考与边界

- GitHub 当前仓库的周期商品详情已经采用“首图 `eager` + `fetchpriority=high`，后图 `lazy`”策略；普通商品复用同一加载优先级，不另造第二套素材协议。
- 浏览器原生 `loading=lazy` 继续作为底层能力，并用 `IntersectionObserver` 控制何时写入后续图片的 `src`；不支持观察器的浏览器回退为原生懒加载。
- OneID：不涉及。只消费既有可信支付会话，不新增身份解析、建客或归属逻辑。
- Persistence：无新增持久化。页面只读现有商品与素材数据。
- External Effects：不涉及。不新增 Provider 调用、任务、Worker、重试或外部效果状态机。

## 验收标准

1. 有素材详情页的 `#detailContent` 中不存在商品名称/描述摘要面板，首个可见业务内容为详情图。
2. 首图标记为 `eager` 和高优先级，通过资格检查后立即请求；后图在接近视口前没有 `src`。
3. 后图进入预加载范围后开始加载；无 `IntersectionObserver` 时仍能显示全部详情图。
4. 接口悬挂超过页面时限后显示可恢复错误状态，不再无限加载。
5. 无素材直达支付、支付恢复、购买后动作及移动端底部购买栏回归通过。
