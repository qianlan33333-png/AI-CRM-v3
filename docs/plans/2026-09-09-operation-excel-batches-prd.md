# 运营闭环 Excel 批次 PRD 与开发交付计划

状态：用户授权子代理开发；未授权本轮部署、生产迁移、恢复组件或真实发送。

## 1. 目标与交付范围

运营人员在运营闭环完成长期计划下的 Excel 上传、卡片预览、人审、创建企微任务和效果查询，所有操作留在同一详情页。API 可上传待审核批次，不能因上传自动批准或发送。长期计划由 AI 调现有受控接口创建，前端没有新建长期计划入口。

一级列表每行是长期计划，右侧仅查看详情。详情顶部是计划名称、当前批次、当前进度、历史批次选择器、新建发送批次。默认最近批次，可同时有多个批次在观察。详情左侧仅两个维度：内容准备与发送、发送效果与复盘。历史切换同时切换内容、回执和报告，不跨批次混合。

## 2. 已确认输入与操作行为

Excel 按列名读取，全部文本处理：unionid、话术、小程序 path、发送人 userid、标题。前四列非空；标题列必需但单元格可空，空标题行允许审核展示，在执行阶段记失败且不调用企微创建任务。可选列“分层”仅 A/B/C/D 或空；非法值返回 Excel 行号和错误，不能静默降级。列顺序不受限。重复 UnionID 返回行级错误，不能重复触达。保留当前合理文件大小/行数及安全校验限制，API 文档注明实际值。

统一封面由页面或 API 上传，批次级 PNG/JPEG，不超过现有 2MB；固定配置 AppID，不查询或生成标题、封面、分层。没有封面禁止批准，前后端均检查。预览显示 UnionID、员工 userid、话术、标题、path、封面、可选分层、状态及修改/排除按钮。修改可选分层与其他内容一样参加版本及审核控制。

未提交批次可整份替换 Excel；保留原批次编号、已上传封面，替换全部当前行，重新审核，保留旧上传内容版本与审计。替换不产生第二个可发送计划，不继承旧行的批准或排除。旧版本可只读查看。并发替换、编辑、换封面、提交使用版本冲突保护；已提交批次禁止修改。替换旧文件与同文件重复上传要区分命令范围，不能把另一个批次内容误绑定。

同文件再次上传默认提示已有批次及其所属计划，不跳到错误计划或覆盖已有文件；明确“创建新的发送批次”后才能再次创建。每次 API 写请求必须带幂等键，同命令同键重试返回原结果，同键不同内容冲突。新建按钮启动上传草稿流程，可在上传成功时持久化新批次，不要求先生成空的数据库计划。

提交按钮为“审核通过并创建企微群发任务”。提交前展示总行数、排除数、空标题数、预计任务数。一次点击完成审核与创建意图，沿用现有权限/CSRF/预览证明，不增加第二次 CRM 确认。提交后冻结最终内容、封面及分层。API 上传仅创建待审核记录，不能通过输入状态绕过审核。

## 3. 身份、发送与状态

OneID：涉及外部身份解析；继续经 Identity Port 在执行时解析 UnionID，保留 scope，不自动建客、不猜测匹配，不在上传前检查负责人/好友关系/可达性。

持久化：PostgreSQL 审核、批次关联、幂等、审计与发送意图需同 Unit of Work；Python 既有 SQLite 仅承担原组件职责，不能成为批准状态权威。内部观察任务复用 River/jobqueue；Provider 读取沿用回执适配器；企微业务写只经 Outbound 与 External Effects。禁止新建发送队列、重试引擎、跨领域表写或第二套身份匹配。

逐人状态沿用底层事实并显示中文：未批准、待提交、任务已创建待员工执行、发送成功、明确失败、结果待核实，排除单独展示。受理/排队/超时均不等于成功。完整分页、唯一接收人回执和实际 send_time 才能证明送达。结果未知先对账，不能换 key 重发。保持逐接收人任务方式，员工在企微端执行。

## 4. 效果与分层

始终提供总体统计。Excel 分层列缺失或全空时仅显示总体；存在有效分层时显示实际存在的 A/B/C/D，空值显示未分层。总体包含所有成功发送用户，包括未分层。剔除/失败/未执行不进入成功发送分母。分层是本次审核采用的 Excel/编辑值，不再调用 segment_sql，不沿用旧自动分群快照。历史旧批次分群来源不得伪装成 Excel 来源。

按每人实际成功发送时间算累计 12/24/48 小时。打开是对应 path 内容打开，不要求本次发送卡片来源，同一人重复打开计一人。每窗口打开率分子为已满窗口且窗口内打开的人数，分母为已满窗口成功发送人数。观察未满单列。路径未知、身份不唯一、日志覆盖不足或源错误单列暂不可统计；分母内存在缺失则率为 null，不能把缺失计零或缩小分母。总体和分层使用同一计算器。

报告提供成功发送人数、已满窗口、观察中、打开人数、数据缺失、打开率；显示采集时间，支持逐人下载。每五分钟沿用持久任务重新读取完整分页回执与有界窗口内容事件，晚到允许补算，重启恢复。源覆盖未证明时诚实显示不可统计，不配置无条件 coverage=1。

## 5. 接口与复用策略

优先复用 V3 已有 operationcycle 长期计划、aiassistant 审核/Excel bridge、outbound 回执、Python parse/observe、webshell 页面；使用受控 Port/组合根适配，不能业务领域互相 import store/app。业务体验不因内部仍复用 aiassistant 而跳页面。

交付接口能力：指定长期计划的批次创建/上传、列表、单批次/旧版本读取、Excel 替换、封面上传、逐行内容与分层修改、排除、预览批准及批准、回执、观察报告/下载。由后端负责人先发布精确路由和 JSON/上传参数契约，前端依据同一文档实施，不平行发明字段。页面与 API 必须同权限、校验、版本和幂等语义；不新增公开管理入口或无认证 API。

所有新上传必须指定可访问且存在的长期计划。旧未关联 Excel 批次不自动挂载；提供受控显式关联命令（同批次只关联一次、存在性/权限/幂等/审计），无前端通用迁移入口。不操作生产验收草稿。AI 助手保留非 Excel 来源；已关联 Excel 在运营闭环展示，旧详情链接应受权后引导新详情，未关联旧批次保留只读可发现性，不静默丢失历史。
