# Excel 独立发送与素材每日全量刷新：实施与验收

## 授权与基线

用户已确认执行本地开发和测试。本轮不推送、不合并、不部署、不修改生产配置、不进行真实企微上传或消息发送。隔离分支 `codex/daily-media-refresh`，基线 `dc640ee`。

OneID：不新增身份机制，发送继续复用现有 Identity Port。持久化：Media 原文件和引用、Outbound 媒资准备和 Provider 凭据、External Effects 执行状态各有唯一 Owner。每日扫描属于现有 River 内部持久任务；企微上传和消息写继续经 Outbound + External Effects。业务状态、幂等、审计、Outbox、效果接受在必要时共用 PostgreSQL UoW，不在数据库事务中进行网络上传。

## 已确定行为

- 每天北京时间 02:00 重新上传所有启用、且需要临时 media_id 的素材，不按剩余有效期筛选。每天唯一轮次，分页及进度持久化，重启恢复；同轮成功文件不重复上传。
- Excel 独立 `outbound_excel` 队列 3 并发；素材准备独立 `outbound_media` 队列 2 并发。当前单 effects-worker，不增加主动 QPS 限速或固定请求间隔；明确官方拒绝按安全分类退避。
- 保留已有素材库编号、原文件和冻结内容摘要。临时 media_id 只是 Provider 凭据，72 小时有效期根据 Provider 上传时间计算；不作为业务主键。
- 图片、附件、小程序封面参与；链接不适用。同一企业/接口/type/内容摘要以及必要的展示文件名区分缓存，真实共享文件同轮仅上传一次。不得串用其他企业或不同协议的媒体凭据。
- 新凭据成功才更新当前引用；失败保留尚有效的旧记录。首次准备、重新启用、发送时失效自动准备；发送等待使用既有 River 暂缓并释放发送槽，不能计为已发。
- 未知上传或消息结果不盲目换 key 重试，不按臆测时间自动宣告旧效果失败；沿用明确对账/审计路径。只有有证据确认 Provider 未产生效果的拒绝才允许安全重试。
- 上传单独配置超时，初始 120 秒；消息请求保留既有超时。发送身份/审批/消息幂等不因媒体凭据刷新改变。
- Excel 上传封面自动进入 Media；相同内容启用图复用，停用图不自动恢复。支持选择已有启用图片。批次冻结图片引用和真实内容摘要；凭据刷新不触发重新审核，真实换图仍触发。旧 Python 封面和已提交历史保留，不静默改写。
- 素材库展示刷新状态、最近成功时间、到期时间、失败原因、当日进度及下次运行；提供单素材/全量异步刷新。所有 API 复用管理员权限、CSRF、幂等和审计。没有原文件的旧凭据提示补传。

## 工作包与所有权

1. `media_core`（sol medium）：Outbound/EER/WeCom/River/config，通用媒资缓存、日轮次、等待协议、队列分配、Provider 上传，组合根与 Host/PG 集成。持有0125迁移、共享API契约文档。复杂核心使用一次sol，其余工作保持指定较低成本模型。
2. `media_catalog`（terra high）：Media 原文件/启用枚举/快照/刷新管理接口，Excel 封面绑定，必要 AI/Automation/Python 兼容适配，0126迁移。与core通过稳定Port接入，不跨领域访问表。
3. `media_ui`（luna max）：现有素材库管理界面和Excel选图，精确DOM与前端回归。保持嵌入标题/滚动区，不复制第二个审核入口。
4. 主代理仅负责文档、分工、契约决策和交付审查；业务代码交由子代理完成。共享 Composition 与测试迁移初始化统一由core协调，其他代理不得同时改同一文件。

## 验收要求

- 全量刷新跨日、重启、分页、同轮重试去重、两引用同文件去重；每日强制产生新凭据，而非因旧凭据仍有效就跳过。
- 失败保留旧有效ID、过期等待后恢复、大附件超时独立、unknown不重传、企微明确限流不循环请求。
- Excel 3槽与媒体2槽隔离，不受普通outbound积压影响；等待素材不占发送槽、不记真实attempt、不破坏审批事务。
- Excel上传/选图、停用去重、换图重审、已提交不可改、历史封面字节不变；仅换media_id不影响冻结内容。
- Excel、AI助手、自动化、侧边栏、GroupOps均实际消费统一准备Port，无逐接收人重复上传旁路；不存在第二套发送或上传重试内核。
- API权限/CSRF/idempotency并发及异常投影；DOM的分页、错误、异步按钮和标题布局；真实Go+Python+PostgreSQL/构建后浏览器使用本地Provider fixture完成旅程，不能用静态stub冒充集成。
- 最终按仓库 `fast`、`compile`、受影响专项、完整相关CI阶段执行；PG显式隔离，Chromium强制且不接受静默skip。更新所有受影响的旧测试迁移fixture，不重复前次只测Excel漏掉全仓fixture的问题。

最终交付记录准确HEAD/工作区状态/命令结果，以及未验证的真实Provider吞吐和线上行为；不把本地测试称为上线或真实送达。
